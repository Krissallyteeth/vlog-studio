## 1단계 (최우선) — 검색 근거 제목·본문·해시태그 추천 ✅ 개발됨

> 구현하며 바뀐 점: 爆款 기준은 **좋아요**(검색 카드에 항상 있는 값) 중앙값의 3배 이상, 좋아요를 읽은 노트 5개 미만이면 계산 안 함.

**답하는 질문:** 이 주제로 小红书에서 실제로 터진 글들은 어떤 제목·표지 문구·태그를 썼나?

### 1-a. PC용 작은 수집기 (`tools/collector/`, Python, 검색만, 읽기 전용)
- 사용자가 직접 QR 로그인. 쿠키는 PC 안 전용 Chrome 프로필에만 (저장소 밖).
- 주제 키워드 3~5개 × 상위 노트 약 20개: 제목, 본문 일부, 해시태그, 좋아요·수집·댓글 수, 발행일,
  작성자 팔로워 수(보이면), 노트 유형(영상/이미지), 연관 검색어(검색창 자동완성).
- 버튼을 누를 때만, 적은 요청. 자동화 탐지 숨김 코드 없음. 결과는 JSON 파일 (`private-data/`).
- 먼저 사용자 PC에서 실제 검색 결과에 어떤 항목이 오는지 함께 확인한 뒤 확정.

### 1-b. 앱 "검색 근거" 화면
- JSON 파일 가져오기 → 규칙으로 계산 (AI 없이):
  - **爆款 후보 표시**: 같은 검색 결과 안에서 반응(좋아요+수집) 중앙값의 몇 배인 글.
    작성자 팔로워 수가 보이면 "팔로워 대비 반응"이 높은 글을 우선 (계정 크기보다 콘텐츠 덕분에 터진 글).
  - 爆款 후보들의 제목 패턴: 길이, 숫자·이모지 사용, 질문형/감탄형, 자주 나온 단어.
  - 자주 쓰인 해시태그와 그 태그가 붙은 글의 반응 중앙값.
  - 연관 검색어 목록 (사람들이 실제로 검색하는 말).
  - 수집 수치가 없는 항목은 "미수집".
- "Claude에 붙여넣을 자료 복사" 버튼: 근거 + 내 주제·Hook + 지시
  ("자료에 있는 태그만 사용, 제목마다 근거 노트 표시, 남의 문장 베끼지 않기, 제목 후보 10개·본문 1개·태그 8~10개").

- 고른 제목·태그를 게시물에 저장 → 나중에 성과와 비교 (어떤 패턴이 내 계정에서 통했는지).

- 비용: AI API 비용 없음 (평소 쓰는 Claude 채팅). 필요해지면 나중에 앱 안 호출로 변경.

> 구현: `src/xhs/funnel.js`(판정), `src/views/xhs/funnel.js`(카드), 게시물 상세 5 · 분석 맨 위. D+1/D+2 전환(D+2는 기준선 게시물들의 D+2 중앙값과 비교).

> 광고가 섞인 시점은 판단 없이 수치만 표시(자연 추정 분리는 하지 않음). "추천 제목 사용 글 vs 아닌 글" 비교는 1단계에서 게시물 저장 단계가 빠져 보류.


**답하는 질문:** 추천받은 제목·표지가 실제로 통했나? 다음엔 뭘 고칠까?

- 위치: 게시물 상세 (새 메뉴 없음). 기존 편집 피드백을 확장해 두 화면이 다른 말을 하지 않게 함.
- 5단계와 지표 (모두 이미 저장 중인 값):

  | 단계 | 지표 |
  |---|---|
  | 노출 | 曝光量 |
  | 클릭 | 封面点击率 (제목·표지 효과를 가장 직접 보여줌) |
  | 시청(오프닝) | 2秒退出率, 5秒完播率 |
  | 시청(중후반) | 平均观看时长%, 全片完播率 |
  | 반응 | 互动率, 저장률(收藏÷观看), 공유율(分享÷观看) |
  | 팔로우 | 팔로워 전환율(涨粉÷观看) |

- 판정: 기존 색상 기준(개수 ±20%, 비율 ±10%)으로 양호/부족/미수집. 기준은 기존 고정 기준선.
- 병목: 위 단계부터 부족한 단계 최대 2개 → 정해진 점검 문장. 위 단계가 부족하면 아래 단계는 "참고".
- 1단계 추천을 쓴 글은 "추천 제목 사용" 표시 → 추천 사용 글과 아닌 글의 클릭률 비교 (양쪽 2편 이상일 때).
- 광고 섞인 글: 팔로우 단계는 기존 자연 추정 또는 "광고 포함" 표시.
- 데이터 변경: 없음 (1단계에서 저장한 제목·태그 출처만 추가).

## 3단계 — 유형별 팔로워 전환율 표 (주 유형 + 보조 태그, 협찬 분리) ✅ 개발됨

> 구현: `src/xhs/type-table.js`(표·보조 태그 비교·협찬 옮기기), `src/views/xhs/type-table.js`(대시보드 카드), 게시물 상세 2 · 배포(보조 태그·협찬 체크), 엑셀 AZ·BA 열.

**답하는 질문:** 어떤 콘텐츠가 팔로워를 데려오나?

### 유형 정리 (사용자 결정 2026-11-25)
- 현재: 게시물당 유형 1개(`contentType`), 목록은 데이터 화면 "유형 편집"에서 변경 가능
  (기본: 여행, 일상, 집꾸미기 / 인테리어, 위스키, 음식 / 카페, 협찬 콘텐츠, 기타).
- **주 유형 1개**: 기존 `contentType`을 그대로 주 유형으로 사용 (데이터 변환 없음).
  고르는 기준 = 제목·표지가 약속한 것 (시청자가 무엇을 보려고 눌렀는가).
  예: "새집 꾸미기" 제목이면 중간에 일상 장면이 많아도 주 유형은 인테리어.
- **보조 태그 여러 개** (`subTypes`, 새 칸): 같은 유형 목록에서 선택. 기존 글은 빈 상태로 시작, 필요한 글만 나중에 입력.
- **협찬 체크 분리** (`sponsored`, 새 칸): "협찬 콘텐츠"는 내용 유형이 아니라 협찬 여부.
  기존에 유형이 "협찬 콘텐츠"인 글은 확인 화면에서 → 협찬 체크 + 실제 주 유형 선택으로 옮김 (사용자 승인 후, 자동 변경 없음).
  기존 수익 기록(`income`)에 연결된 글은 협찬 체크를 제안.
- Excel 가져오기·내보내기에 새 칸 추가 (옛 파일은 빈칸으로 가져옴). 기기 간 동기화는 기존 post 기록에 포함되어 스키마 변경 없음.

### 표
- 대시보드에 표 하나. **주 유형 기준으로만 집계** (한 글은 한 번만 셈).
  열: 유형 / 편수 / 조회 중앙값 / 팔로워 전환율 중앙값 / 涨粉 중앙값. 유효(광고 미혼입) D+1 기준.
- 3편 미만 유형은 "참고". 두 유형 비교 문장은 양쪽 2편 이상일 때만.
- 보조 태그는 "○○ 장면이 들어간 글 vs 안 들어간 글" 비교에만 사용 (양쪽 2편 이상, 그룹이 겹치므로 항상 "참고").
- 협찬 글은 필터로 포함/제외 선택 (기본: 함께 보되 표시).
- 완료 기준: 중복 집계 없음 테스트, 협찬 옮기기 확인 화면 테스트(가상 데이터), 기존 유형 통계 결과 변화 없음, PC·폰 화면 확인.
